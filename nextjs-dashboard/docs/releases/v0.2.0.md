## Roll-forward recovery

1. Stop staging writes.
2. Preserve the failed migration output and request ID.
3. Restore the pre-migration staging backup into a separate staging project.
4. Reproduce the failure using `pnpm db:reset` against the disposable local
   stack.
5. Add a new timestamped corrective migration; never edit an already-applied
   migration.
6. Rerun the complete verification suite and rehearse the repair locally.
7. Back up staging again, review the SQL, and apply the corrective migration
   only to staging.
8. Verify migration history, readiness, RLS ownership, and the affected user
   workflow before reopening staging writes.

Workout tables are new in v0.2, so no legacy workout-data conversion is
required.
