# v0.2.0 staging release

## Database

Migration `20260730090000_workout_planning.sql` adds the exercise library,
workout templates, active/completed sessions, mutation receipts, RLS policies,
and transactional RPCs. It seeds 12 deterministic bilingual system exercises.

Corrective migration `20260730110000_workout_experience.sql` constrains the
guided category vocabulary after normalizing unexpected pre-release values to
`other`. Equipment remains user-editable free text.

Apply only to the isolated staging project after taking a staging backup. Do
not apply this migration to production before the v1.0 release review.

## Roll-forward recovery

1. Stop staging writes.
2. Preserve the failed migration output and request ID.
3. Restore the pre-migration staging backup into a separate staging project.
4. reproduce with `pnpm db:reset`;
5. add a new timestamped corrective migration—never edit an already-applied
   migration;
6. rerun verification and apply the corrective migration to staging.

Workout tables are new in v0.2, so no legacy workout-data conversion is
required.

## Deployment gates

- Phase 1 PR #20 is independently approved and merged.
- Vercel Production Branch is the protected `production` branch, not `main`.
- Preview variables target the isolated Supabase staging project.
- Preview derives its own origin from `VERCEL_URL`; it must not redirect to a
  different branch deployment.
- All automated checks and the manual QA matrix pass.
- No production migration or public deployment is performed.
